- **Cloud Hermes:** guest disk networking configuration was edited offline after verified image backups; a persistent VirtIO management interface was attached to the isolated libvirt network. The latest network-acceptance transcript did not inspect the VM state after the reboot. Do not infer VM autostart or guest DHCP success from the Guard/Docker/Squid boot sequence; see [issue #10](https://github.com/ViktorIXAI/claryel/issues/10).
- **P2002 GPU / Strata:** owner-supplied output confirms Strata 0.2.11 readiness, Qwen3.8-Flash-Next IQ3_S loaded, and successful real inference from a disposable peer (48.6 generated tokens/s; 151.3 prompt tokens/s). Docker has no host port binding for 8080 and the host `ss` check found no listener on 8080, but a later direct host request to `172.31.250.2:8080/health` returned HTTP 200 via bridge `br-ffbceca294f9` (`172.31.250.1/24`). The inference network is `Internal=true`, IPv6 disabled; previous container egress tests were bounded to tested endpoints. The profile is root-owned mode `0600` and has neither `api_key` nor `allowed_hosts`; the service is unauthenticated. Strata native Bearer/`x-api-key` support for `/v1/*` is identified. The supplied `inet claryel_guard` and iptables rules cover `virbr240` and the separate proxy bridge `br-strata-eg` (`172.30.250.0/24`), not the inference bridge `br-ffbceca294f9` (`172.31.250.0/24`). Host `OUTPUT` policy is ACCEPT; `DOCKER-USER` is empty; `DOCKER-FORWARD` permits same-bridge forwarding. Guard enforcement for the inference bridge is not demonstrated. Public-WAN/LAN reachability and authentication coverage of non-`/v1/*` routes remain untested. The latest owner-supplied container inspect records immutable image digest `sha256:932700126d693662cbd11623555b9c451c7c678da138455b36bb05607f8d061b`, GPU devices `/dev/kfd` and `/dev/dri`, supplemental groups `993,44`, `unless-stopped` restart, 30s/8s/3-retry/2h healthcheck, writable named `/data` volume and read-only `claryel-strata-models` volume, no published ports, and no privileged mode. Container and image `Config.User` are empty, but the image entrypoint is `/usr/bin/tini -- /opt/strata/entrypoint.sh` with command `run`; owner-supplied in-container checks confirm active Python processes UID/GID 0:0 with supplementary groups 0,44,993. The profile is 0600 root:root; `/data` and `/models` mount roots are 0755 root:root. Docker-configured environment variable names were checked without values; `STRATA_API_KEY` is absent, consistent with `api_key=false`. The prior diagnostic's mount loop was malformed, but the subsequent corrected command successfully checked exact `/data`, profile and `/models` paths. Owner-supplied source inspection now confirms the complete native entrypoint key flow: API_KEY_FILE is read into a shell variable, passed to strata launch via STRATA_LAUNCH_KEY, saved by launch into the private preset and derived run config, and then written again by the entrypoint to the default /data/state/api-key under umask 077. Actual preset/run-config paths and modes and /data backup coverage remain unaudited. The live container overrides that entrypoint with bash and directly runs strata serve --profile; the direct server accepts STRATA_API_KEY or profile api_key. A file-reading wrapper for the current serve path remains only a candidate pending targeted persistence/logging review and disposable dummy-key testing. No production secret was created. See [the inference/security checkpoint](../logs/P2002/2026-11-07-strata-private-api-inference-success.md), [log inventory](LOG-INVENTORY-AND-GAPS-2026-11-07.md), [issue #9](https://github.com/ViktorIXAI/claryel/issues/9) and [issue #16](https://github.com/ViktorIXAI/claryel/issues/16).

## Reading rules

1. Git history proves a publication history, not that every described shell action occurred.
2. Explicitly distinguish OWNER_REPORTED, TOOL_OBSERVED, INDEPENDENTLY_VERIFIED, SIMULATED, PROPOSED and UNKNOWN.
3. A passing policy verifier is not a traffic test. A passing bounded traffic test is not proof against every protocol or bypass.
4. Preserve mistakes, failed hypotheses, aborted attempts and corrections in new dated artifacts; do not silently rewrite the ongoing P2002 installation journal.
5. Owner-supplied terminal output is not independent execution by the documentation author.
6. Check the latest chronological checkpoint and unresolved issues before taking installation action. This index cannot authorize operations.

For future events use [the checkpoint template](../templates/AUDIT-CHECKPOINT.md). No production or security-certification claims are made here.
